Class: Challenge

Challenge()

Merkle-leaf availability challenge for a sealed blob tree. A **commitment** is the provider's signed promise to hold a tree (root, `blobTotal`, publisher) until an epoch, optionally naming the deposit that backs it. A **challenge** is the publisher's signed, Beacon-epoch stamped request for one leaf; the leaf index is derived from the challenge nonce so neither party picks it. A challenge may commit an **answer hash** `SHA256(SHA256(nonce || blob bytes))`, also committed in that round's deposit output as the provider's unilateral `answer` leaf (see `Bond.buildDeposit`), so the provider can always answer on-chain. A **response** is the provider's signed inclusion proof plus the nonce-bound possession digest. A **receipt** is the counterparty's signed acknowledgement of a challenge (and response) at an epoch; an **epoch attestation** is a Beacon / federation key's signature that a digest existed at an epoch. All are plain JSON artifacts carried as `CONTRACT_MESSAGE` bodies and feed Witness.FraudProof. Response deadlines are expressed in **epochs** (default two) so a lagging Hub view cannot make an honest provider provably late.
