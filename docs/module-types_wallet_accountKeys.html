Module: types/wallet/accountKeys

One seed, many accounts, three separate keys each. A user imports one mnemonic (plus an optional BIP39 passphrase) once; the client keeps only the resulting master xprv, sealed by a separate lock password. From that master, every (account, network) pair derives: - a Fabric identity key `m/7777'/F'/n'/0/0` (F = 7777 on mainnet, 7778 elsewhere), the only key a sign-in proves; - a Bitcoin wallet: `m/84'/B'/n'` (SegWit, every new receive and change address), `m/86'/B'/n'` (BIP-86 Taproot `tr`, for Taproot payments and contracts), and `m/44'/B'/n'` (standard `pkh`), the last two watched and spendable but never handing out receive addresses here; B = 0 on mainnet and 1 elsewhere; - a multisig cosigner key `m/87'/B'/n'/0/0` for group wallets, escrow, and federations — never the identity key. Wallet xpubs are shared with depth, parent fingerprint, and child number zeroed and no key origin, so xpubs from two accounts can't be linked to one seed.
