(static) buildCommitment(funding, state, opts) → {object}

Build the (unsigned) commitment transaction **held by one party** for a channel state (asymmetric, BOLT 3 shape): spends the funding output through the `cooperative` leaf into the holder's delayed/revocable `toLocal`, the counterparty's plain `toRemote`, one output per pending HTLC (holder leaves CSV-delayed and revocable), and two anchor outputs. Deterministic for identical inputs, so both peers derive the same `txid` and only exchange tapscript signatures on *each other's* commitment.

(static) buildHtlcOutput(opts) → {object}

Per-HTLC P2TR output on a commitment. Symmetric form (no `revocationPubkey`): `claim` hashlock leaf for the receiver and `timeout` leaf for the sender after `expireAfter`. Holder-aware form adds a `revocation` leaf and a `toSelfDelay` CSV on whichever leaf pays the commitment *holder*: the holder is punished for a stale broadcast and must wait on their own tx. On the **receiver's** commitment the sender's timeout additionally waits `toSelfDelay + htlcClaimWindowBlocks` (CSV) after confirmation, so the receiver's CSV-delayed claim can never be raced by a CLTV-only timeout — this replaces BOLT 3's second-stage HTLC-success transaction. On the sender's commitment the receiver claims immediately and the sender's timeout waits `toSelfDelay`.
Parameters:
Name Type Description
opts object `{ network, paymentHashHex, receiverPubkey, senderPubkey, expireAfter, holder?: 'receiver'|'sender', toSelfDelay?, revocationPubkey? }`

(static) buildHtlcOutput(opts) → {object}

Per-HTLC P2TR output on a commitment. Symmetric form (no `revocationPubkey`): `claim` hashlock leaf for the receiver and `timeout` leaf for the sender after `expireAfter`. Holder-aware form adds a `revocation` leaf and a `toSelfDelay` CSV on whichever leaf pays the commitment *holder*: the holder is punished for a stale broadcast and must wait on their own tx.
