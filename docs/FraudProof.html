Class: FraudProof

FraudProof()

Self-contained proof that a market counterparty broke a signed obligation. Shape: `{ type: 'FraudProof', kind, artifacts, claim }`. `verify()` is pure over the artifacts; the few kinds that assert an **on-chain fact** (a broadcast happened, an outpoint is unspent, the tip passed a height) take that fact from `ctx` — the verifier's own chain view, which must describe **confirmed** state at least `ctx.minConfirmations` (default 6) deep — and refuse to conclude without it. No kind infers fraud from a *missing* message alone, and no kind trusts a time its accused party could backdate. Every challenge-based kind binds the challenge to the provider's signed `AvailabilityCommitment` (root, `blobTotal`, publisher) and recomputes the challenged index from the nonce. A verdict carries `reputational: true` only when it may move a reputation score. Kinds: - `wrong-leaf`: challenge + commitment + provider-signed response whose leaf is not at the challenged index of the committed tree, or (with a Merkle proof of the publisher's pin) names another blob hash. - `non-response`: challenge + commitment and either (a) a provider-signed response after `deadlineEpoch` **plus** an anchor showing the challenge reached the provider in time — a provider-signed `AvailabilityReceipt` or trusted `EpochAttestation`s (`ctx.beaconPubkeys`) — or (b) **timelock evidence**: the provider's `DepositPenaltyPreSig` for the deadline, past `deadlineHeight + confirmations`, with the deposit outpoint neither checked in nor answered. (b) names the provider as offender only when the provider had a unilateral way to answer: the pre-signature acknowledges this challenge (`challengeHash`), the challenge commits `answerHashHex`, and `artifacts.answerPath` proves the deposit output carries the provider's `answer` hashlock leaf for it. Otherwise the publisher could manufacture the silence (by refusing to co-sign check-in), so the verdict is `offender: null`, `reputational: false` — the pre-signed penalty is enforceable, but it is **not** proof of non-response. - `wrong-answer-hash`: challenge + commitment + the challenged blob's bytes and branch; the answer hash the publisher committed cannot be opened by those bytes — publisher fraud (it would make an honest answer impossible). - `wrong-bytes`: seller-signed `DocumentOffer` (documentId, root, blob index, blob hash, payment hash) + the claim preimage + the seller-signed AMP `P2P_FILE_SEND` frame for the same document / root / index / payment whose bytes miss the offered `blobHashHex`. - `bad-key`: same artifacts for a sealed offer, but the bytes **match** `blobHashHex` and the revealed key K (the claim preimage) does not open them: AES-GCM authentication fails, or the plaintext misses the offered `plaintextSha256`. - `wrongful-penalty`: challenge + the provider's valid, Merkle-proven response + an un-backdatable anchor that it existed by the deadline (a publisher-signed `AvailabilityReceipt`, or trusted `EpochAttestation`s over the response hash) + the penalty transaction that spent the deposit outpoint anyway — publisher fraud. The provider's own `epoch` / `height` fields are never trusted. (An on-chain answer spend needs no such proof: it consumes the outpoint, so no penalty can follow it.) - `stale-commitment`: a payment-channel party's signed `ChannelRevoke` (channel, number, `perCommitmentSecret` opening `perCommitmentPoint`, revoked txid) plus that transaction and evidence it confirmed. Assumes asymmetric commitments: each party holds only its own commitment, so a broadcast of the revoked txid can only have come from the revoker.

(static) checkPenaltyPsbt(psbt, expect) → {Object}

Structural checks every penalty PSBT must pass before anyone signs it and whenever a pre-signature is verified: exactly one input, on the challenged deposit outpoint; a non-final nSequence (else nLockTime is ignored); `nLockTime` equal to the deadline, which must be a block height; every output paying the publisher-named destination (at least `minValueSats`); and a fee no larger than `maxFeeSats` (default 20000). Without a named destination the result is `enforceable: false` — the provider, who signs first, would choose where the penalty pays.
