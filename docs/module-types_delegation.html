Module: types/delegation

Delegation: one Fabric key holder asks another to sign. Participants (Passport, a Hub, GoonCitizen, any Fabric key) never share keys or storage. Everything between them is a signed Fabric Message frame, carried as a `fabric:` string through a rendezvous or a mailbox: - Pairing, so each learns the other's key: `DELEGATION_LINK_OFFER` commits to the initiator's nonce, `DELEGATION_LINK_ANSWER` brings the responder's nonce, `DELEGATION_LINK_REVEAL` opens the commitment. Both screens then show the same six-digit code (sas); neither side could choose its nonce after seeing the other's, so a relay in the middle matches it with odds of one in a million. - `DELEGATION_GRANT`: the author lets `grantee` ask it to sign, for listed scopes (`identity`, `passport`, `federation`, `message`) and optional origins / networks. It discloses the author's cosigner key with a proof, so grants are enough to build a shared federation wallet. A grant runs one way; two `identity` grants, one each way, mean "the same person". - `DELEGATION_REVOKE` withdraws a grant. - `DELEGATION_REQUEST` embeds one frame for the target to sign: a `PASSPORT_CHALLENGE` (answered with a `PASSPORT_ASSERTION`), a federation `CONTRACT_MESSAGE` (an invite or a withdrawal request), or an unsigned chat / generic message. The target answers with a `DELEGATION_RESULT` holding the answer frame or a refusal. - `DELEGATION_MAILBOX_FETCH` proves a reader holds the key whose mail it asks for. Authority always comes from the recipient's own grants (authorize); a rendezvous or mailbox only carries frames. The frame builders and readers are statics on Delegation (and plain properties of this module), so `require('@fabric/core/types/delegation').createGrant` works without a participant. A `Delegation` instance is one participant's side: each participant (Passport, a Hub, GoonCitizen) builds its own `Delegation` with its own key and its own store; nothing is shared between them. It keeps every delegation frame it sends or receives (replayable as a `FabricMessageCollection`), its pairings, the grants it made and received, revocations, and the requests it was asked and asked of others. Incoming frames go to Delegation#receive. An authorized request is stored as pending and emitted as `request` with the notification to show; the app answers with Delegation#sign or Delegation#decline, and sends the returned frames where they need to go (a rendezvous, a mailbox, a loopback reply). This class never talks to the network itself. Events: `request` `{ hash, read, notification }`, `result` `{ hash, request, read }`, `grant` `{ hash, read, direction }`, `revoke` `{ grant, hash }`, `link` `{ linkId, sas, peer, role }`.
