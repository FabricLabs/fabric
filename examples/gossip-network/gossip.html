How the public Fabric network talks

A first-principles walkthrough. Scroll to move the mesh. Nothing here is a website API — it is Peers carrying signed postcards for each other.

A handful of Peers, not a crowd.

    01 · the idea

    A network with no center

    The public Fabric network is not a site you log into. It is a handful of programs — Peers — on different computers that speak the same small language over the internet.

    Each Peer remembers a few neighbors, not the whole world. Messages hop from neighbor to neighbor. That hop-and-copy pattern is gossip.

    Playnet seeds today: hub.fabric.pub:7777 and relay.goon.vc:7777. goon.vc itself is only an HTML zipper — it is not a Peer.

    02 · identity

    You are a key

    A Peer is not a username. It is a cryptographic key. When you send anything public, you sign it. Anyone can check the signature. Nobody has to ask a server who you are.

    That signature stays attached to the original author even after the postcard has passed through a dozen strangers. Relays carry. They do not become the author.

    03 · the hallway

    First, a private hallway

    Before gossip, two Peers open a TCP connection and wrap it in NOISE. Think of that as a private hallway between two machines: hello, keepalive, goodbye.

    The hallway is session control. It is not the public square. Ping and pong live here. So do session offer and session open. Gossip only starts once the hallway is up.

    04 · handshake

    Offer, then open

    One side sends SESSION_OFFER. The other checks it and answers SESSION_OPEN. After that both are READY.

    Default listen port is 7777. Identity on the wire is the Fabric public key, not an IP address. IPs are just how the hallway is built this time.

    05 · the postcard

    Every public message is a signed envelope

    Fabric calls this AMP. A 208-byte header, then a body. Magic bytes so you know it is Fabric. Version 0x01. Who wrote it. What kind it is. How long the body is. A hash of those body bytes. A BIP-340 signature over the frame.

    If the hash does not match the body, the postcard is trash. Neighbors drop it before they even look at the signature. Truncated noise is not treated as a hash mismatch — that would punish an honest neighbor for a partial read.

    06 · the gate

    Check, then carry

    A gossip node does three checks, in order:

    1. Size — not shorter than the header, not larger than the cap (32976 bytes on the wire by default: 208-byte header + 32 KiB body).
    2. Body hash — double-SHA256 of the body must equal the header field.
    3. Signature — BIP-340 must verify for the author key.

    If those pass, the Peer forwards the exact bytes. It does not rewrite the hop count. It does not re-sign. It does not “improve” the message.

    07 · what floods

    Only a few kinds are public

    There are 76 named wire types. Ten of them are the public flood: discovery and peering offers, nicknames, the shoutbox, contract namespaces and proposals, Bitcoin tips, document requests when you do not hold the file, and a rare outer envelope (P2P_RELAY).

    Inventory request/response can flood too, but only if an operator turns that on. Chain rewind is trusted peers only. Everything else stays in the hallway, takes a directed path, or is observed locally and not re-flooded.

    08 · bit-identical

    The copy is the original

    Because relays forward the same bytes, the signature still belongs to you at every hop. The TCP neighbor is not the AMP author. Peer therefore skips “signer must equal this socket” for flood types — otherwise honest relays would be banned for carrying your postcard.

    Exact duplicates are dropped by a wire-hash cache. A second signature on the same logical contract publish is a different kind of duplicate — first writer wins.

    09 · three public conversations

    Discovery, shoutbox, namespaces

    Topology — P2P_PEER_GOSSIP and P2P_PEERING_OFFER say who can be dialed. Budgets keep that from becoming a storm.

    Shoutbox — P2P_CHAT_MESSAGE is cleartext on purpose. Every hop can read it. That is the public square, not a private chat.

    Contracts — CONTRACT_PUBLISH mints a namespace. CONTRACT_MESSAGE carries application events inside it. A relay can flood those without keeping a contract notebook.

    10 · the other road

    Secrets do not gossip

    Private delivery uses P2P_FORWARD: a directed onion to one next hop. File bytes, MuSig2 signing rounds, and Lightning channel frames are also hop-by-hop. They are not shouted across the mesh.

    After someone unwraps an outer envelope, the inner postcard is for local eyes only. The last hop must not flood it a second time. That rule is how a hostile inner message cannot cut the honest link that carried it.

    11 · why it does not melt

    Copies multiply, so there are budgets

    Gossip hop is advisory — it is not decremented, because decrementing would change the bytes. Diameter is controlled with dedup plus a per-origin cap (default 60 topology frames per minute; 30 for shoutbox).

    New neighbors start at score zero. A bad hash or a bad signature is a hard disconnect, not a polite warning. Junk cannot fill the duplicate cache: a frame is remembered only after hash and signature succeed.

    12 · follow one shout

    You say something. The square hears it.

    You sign a P2P_CHAT_MESSAGE. Alice checks the envelope and floods the same bytes. The relay in the middle does the same. Bob and Dest receive what you signed — not a paraphrase.

    Every hop could read it. If you needed privacy, you would not have used the shoutbox. You would have used a sealed group message or a directed forward.

    13 · a carrier only

    A node that just carries

    scripts/gossip-relay.js starts one Peer. No Hub HTTP, no Bitcoin wallet, no Discord, no document shop, no contract state. It validates and floods.

    That is the public network in miniature: hallway, gate, carry. Applications (Hub, GoonCitizen, Passport) sit on top. They are not the gossip fabric itself.

    node scripts/gossip-relay.js --list-types
node scripts/gossip-relay.js --port 7777
