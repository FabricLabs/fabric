# `@fabric/core` Changelog
Recent changes to Fabric Core.

## 2026-10-25
- **Signed books evict the incoming signer's cancel on a tie.** When the cancel table is full, a signed book (`LiquidityBook`, `CoinjoinBook`) counts the cancel being added toward its signer when choosing whose oldest cancel to drop. A maker that ties another maker now loses its own cancel, so it can no longer flush the other maker's cancel and let that maker's still-signed entry back into the book.
- **Oversized documents fail early.** `Document.split` refuses content that would need more than `MAX_DOCUMENT_BLOBS` blobs at the given chunk size before hashing any (it used to hash every chunk, then throw from the root). `Peer` warns and sends nothing for such a document instead of throwing out of a `P2P_FILE_SEND`. `Document.verifyBlobIndex` returns `{ ok: false, error }` for too many leaves or a malformed `paymentHashHex` instead of throwing.
- **`Market` never pays for an unsealed blob (behavior change).** An unsealed sale is not atomic: the seller can claim the HTLC (L1 or channel) without delivering, because nothing the buyer needs is behind the preimage. `Market` now plans and opens only free unsealed offers; paid offers must be sealed (`openSession` refuses the rest). `DocumentBook` drops paid unsealed offers whenever a sealed offer is listed, and always with the new `paidSealedOnly` option of `pickBest` / `pickBlobPlan`.
- **`functions/documentBlobManifest` is removed (breaking, no shim).** The blob index and document tree become `Document` statics (`types/document`), and the transfer book gets its own type, `types/documentBlobTransferBook` (`DocumentBlobTransferBook`, default export). Statics never use `this`, so `const { verifyBlob } = require('@fabric/core/types/document')` works. Trees, indexes, payment hashes and frames are byte-identical. **Renamed:** `splitBlobs` → `Document.split`, `buildBlobIndex` → `Document.blobIndex`, `compactBlobIndexForWire` → `Document.compactBlobIndex`, `advertiseDocumentBlobs` → `Document.advertise`, `merkleRootHexFromBlobHashes` → `Document.rootHexFromBlobHashes`, `documentLeafHex` → `Document.leafHex`, `documentMerkleRootHex` → `Document.rootHex`, `documentInclusionProof(s)` → `Document.inclusionProof(s)`, `verifyDocumentInclusion` → `Document.verifyInclusion`, `blobPaymentHashHex` → `Document.blobPaymentHash`, `DEFAULT_BLOB_CHUNK_BYTES` → `Document.CHUNK_BYTES`, `SEALED_BLOB_CHUNK_BYTES` → `Document.SEALED_CHUNK_BYTES`, `SEALED_FRAME_JSON_OVERHEAD` → `Document.SEALED_FRAME_OVERHEAD`, `MAX_DOCUMENT_BYTES` → `Document.MAX_BYTES`, `parseFileSendObject` → `DocumentBlobTransferBook.parseFrame`, `verifySealedBlobFrame` → `DocumentBlobTransferBook.verifySealedFrame`, `MAX_PENDING_BLOB_TRANSFERS_PER_ORIGIN` → `DocumentBlobTransferBook.MAX_PENDING_PER_ORIGIN`; `sameIv`, `verifyOfferLeaves`, `verifyBlobIndex`, `verifyBlob`, `reassemble` and `BLOB_INDEX_TYPE` keep their names on `Document`. `settlementDedupeKey` moves to `types/documentBook` (static and named export). Import `MAX_DOCUMENT_BLOBS` and `MAX_MESSAGE_SIZE` from `constants`. **Removed:** `DEFAULT_CHUNK_BYTES`, `LEGACY_HUB_CHUNK_BYTES`, `BLOB_MERKLE_ALGO`, `FILE_SEND_JSON_OVERHEAD`, `ivBytes`, `normalizeChunkBytes`, `transferKey`, the transfer TTL and pending-cap constants, `Market.settlementDedupeKey`, and the `blobPaymentHashHex` re-export from `functions/documentPaymentHash` and `splitBlobs` from `functions/documentSealedExchange`. Hub, GoonCitizen and Passport move to the new names in the same change.
- **Contract tip helpers become `Contract` and `Program` statics (breaking, no shim).** `functions/contractSpend`, `contractPaymentObserve`, `contractCapability`, `contractPublishAuthority` and `contractIdentifier` move onto `Contract` (`types/contract`), and `functions/contractProgramBind` onto `Program` (`types/program`). Statics never use `this`, so `const { resolveSpend } = require('@fabric/core/types/contract')` works; `Federation` and `Bond` inherit them. Spend policies, withdrawal request ids, witness signing messages, capability tokens and PSBTs are unchanged. **Renamed onto `Program`:** `programMetaFromTip` → `Program.runFromTip`, `requiresProgramBind` → `Program.requiresBinding`, `bindProgramRunToTip` → `Program.bindRun`, `validateProgramRunBinding` → `Program.validateBinding`, `assertMachineRunMatches` → `Program.verifyMachineRun`, `programRunId` → `Program.runId`. **Renamed onto `Contract`:** `normalizeArcGenesis` → `Contract.normalizeGenesis`, `observePaymentToAddress` → `Contract.observePayment`, `applyPaymentObservationToTip` → `Contract.applyPaymentObservation`, `issueContractCapability` → `Contract.issueCapability`, `verifyContractCapability` → `Contract.verifyCapability`, `collectContractAuthorityPubkeys` → `Contract.authorityPubkeys`, `authoritySetHasPubkey` → `Contract.hasAuthority`, `contractPublishSignerAuthorized` → `Contract.publishSignerAuthorized`, `normalizeContractIdentifier` / `resolveContractIdentifier` / `stampContractIdentifier` → `Contract.normalizeIdentifier` / `resolveIdentifier` / `stampIdentifier`, and the constants to `Contract.WITHDRAWAL_REQUEST`, `WITHDRAWAL_WITNESS`, `OP_CONTRACT_READ`, `OP_CONTRACT_SIGN`. `resolveSpend`, `tipSpendKeys`, `canonicalSpendPolicy`, `nestBitcoinAnchor`, `toCompressedPubkeys`, `roleToCapability`, `capabilityToRole` and the withdrawal request / witness functions keep their names on `Contract`. `normalizePeerPubkeyHex` moves to `functions/pubkey`. **Removed:** the six modules, and the `parseBitcoinTransaction` / `outputScriptForAddress` exports (now private to `types/contract`). Errors that named the old functions now start `Program.bindRun:` / `Contract.applyPaymentObservation:`. Hub and GoonCitizen move to the new names in the same change.

## 2026-10-24
Books and HTLCs move into types, and helpers move onto `Message`. **Breaking:** the old modules are removed rather than kept as shims; importers must move to the new paths below.

- **`types/htlc`** (`Htlc`, also `Fabric.Htlc`): the P2TR claim / refund HTLC is now built from `Policy`'s leaf builders, with instance methods (`address`, `controlBlock`, `findVout`, `prepareClaim`, `prepareRefund`) and statics for the old functions. Addresses, scripts, control blocks and PSBTs are byte-identical to before (pinned in `tests/fixtures/htlc-vectors.json`). **Removed:** `functions/inventoryHtlc` and the `Wallet.buildInventoryHtlcP2tr` / `Wallet.buildHtlcFundingHints` statics. Build with `new Htlc({ network, claimPubkey, refundPubkey, paymentHash, refundLocktime })` (the old `networkName`, `sellerPubkeyCompressed`, `buyerRefundPubkeyCompressed`, `paymentHash32`, `refundLocktimeHeight` names are not accepted); `htlc.fundingHints({ amountSats, label })` replaces `buildHtlcFundingHints`; `Htlc.validateOffer` takes the same settings plus `paymentAddress` and returns the `Htlc` as `htlc` (was `built`). `buildDocumentOfferEscrow` is gone with no replacement. Old function → static: `hash256` → `sha256`, `randomPreimage32` → `randomPreimage`, `prepareInventoryHtlcSellerClaimPsbt` → `prepareClaimPsbt`, `signAndExtractInventoryHtlcSellerClaim` → `signClaim`, `prepareInventoryHtlcBuyerRefundPsbt` → `prepareRefundPsbt`, `signAndExtractInventoryHtlcBuyerRefund` → `signRefund`, `extractPreimageFromClaimTx` → `extractPreimage`, `extractPreimageFromWitnessStack` → `extractPreimageFromWitness`, `refundLocktimeMature` → `refundMature`, `toXOnlyPubkeyHex` → `toXOnly`, `findP2trVoutForAddress` → `findVout`, `buildTapLeafControlBlock` → `controlBlockFor` (`buildClaimControlBlock(c, r)` is `controlBlockFor(c, r, c)`, or `htlc.controlBlock('claim')`); `signerFromPriv32` and `pubkeysMatchXOnly` keep their names. `TAPROOT_INTERNAL_NUMS` and `networkForFabricName` come from `Policy` (`types/policy`), and the BIP-371 helpers from `functions/bip371`.
- **Maximum document size doubles:** `MAX_DOCUMENT_BLOBS` is 8192 (was 4096), so `MAX_DOCUMENT_BYTES` is 197,394,432 bytes (≈ 188.3 MiB) and a sealed frame carries up to 13 proof siblings, still within `SEALED_FRAME_JSON_OVERHEAD`. A full-size document still fits the 256 MiB pending budgets. Peers on the old limit refuse documents over 4096 blobs.
- **Network names:** there is one `networkForFabricName`, on `Policy`. **Behavior change:** HTLCs built with the network name `'test'` now use mainnet parameters, as the contract spend ladder always did; before, `inventoryHtlc` mapped `'test'` to regtest. Pass `'regtest'` for regtest addresses.
- **Book family:** `Actor` → `Book` → `SignedBook` → `OrderBook` → `CoinjoinBook` / `LiquidityBook`, plus `Book` → `DocumentBook` and `Book` → `ChannelBook`.
  - **`types/book`** (`Book`) is now the capped, keyed, insertion-ordered store at the root of every book. It extends `Actor` (was `EventEmitter`); Actor state holds only `{ type }` (the subclass name), so settings, keys and rows stay out of `state`, `toJSON` and `id`. `SignedBook#get(id)`, `ChannelBook#get(channelId)` and `ChannelBook#export` / `import` replace the Actor methods of the same names.
  - **`types/signedBook`** (`SignedBook`): signed entries, expiry, cancels before and after the entry arrives, and dropping a maker. `SignedBook.codec({ name, version, normalizers, signerField })` builds a market's signed-body codec (`toBody`, `fromBody`, `signingString`, `bodyId`, `pubkeyFromPrivate`, `signBody`, `verifyBody`, `randomNonce`); `types/coinjoin` and `types/swap` carry their codecs as `Coinjoin` / `Swap` statics, with the same bodies.
  - **`types/orderBook`** (`OrderBook`): what the coinjoin and liquidity books share, namely `ingest(body)`, `list(filter)` (maker filter plus the market's own), `makers()`, and an optional per-maker cap. **Renamed:** `CoinjoinBook#ingestOffer` / `LiquidityBook#ingestOrder` → `ingest`, `CoinjoinBook#listOffers` / `LiquidityBook#listOrders` → `list` (same filters and rows). The private `_offers` / `_orders` aliases and the `MAX_CANCELLED` / `MAX_PENDING_CANCELS_PER_MAKER` re-exports on `types/liquidityBook` are gone (they are on `types/signedBook`).
  - **`types/documentBook`** (`DocumentBook`): the document / blob offer book, which was `Book` in `types/book`, with the same methods. It also carries the purchase-session, private-relay and inventory-paging functions as statics and named exports: `createDocumentPurchaseSession`, `findSession`, `isDuplicateSettlement`, `rememberSettlement`, `listRefundCandidates`, `computeRelayFee`, `buildForwardedDocumentRequest`, `assertMonotoneBudget`, `paginateInventoryItems`.
  - **`types/channelBook`** (`ChannelBook`): the payment-channel session registry, which was `Channel.Book` in `types/channel`, now a `Book` whose rows are the sessions. It never evicts: past `maxEntries` (default no cap) `add` / `open` / an inbound `ChannelOpen` throw `ChannelBook: full`. Tip times use the book clock (`now`). **Removed:** `Channel.Book` (import `types/channelBook`) and the `sessions` Map (use `get(channelId)`, `has`, `size`). `Channel.expireHeight` (an HTLC row's CLTV height) is now public.
  - **Removed:** `functions/documentMarket` (import `settlementDedupeKey` from `functions/documentBlobManifest`), `functions/inventoryPages`, `types/offerBook` and the `DocumentOfferBook` name, and the `Book` / purchase-session re-exports from `functions/cliDocumentExchange`.
- **`types/swap`** (`Swap`): the L1/L2 swap settlement state machine, which was `LiquiditySwap` in `types/liquiditySwap`, now also carries the market helpers from `functions/liquiditySwap` as statics (`Swap.quote`, `Swap.normalizeOrder`, `Swap.signBody`, `Swap.validateTake`, …). **Renamed:** `swapRoles` → `Swap.roles`, `buildSwapEscrow` → `Swap.buildEscrow`, `validateSwapEscrow` → `Swap.validateEscrow`, `validateSwapInvoice` → `Swap.validateInvoice`. Errors start with `Swap:` (instance) and `swap:` (bodies). `toJSON` writes `type: 'Swap'` and `fromJSON` accepts only that, so swaps saved as `LiquiditySwap` must be finished on the old code. Wire bodies (`LiquidityOrder`, …, `LiquiditySwapFunded`) and their signing strings are unchanged. **Removed:** `functions/liquiditySwap`, `types/liquiditySwap`.
- **`types/coinjoin`** (`Coinjoin`): the coinjoin round base (was the private `RoundBase` in `types/coinjoinRound`, now the parent of `CoinjoinTakerRound` / `CoinjoinMakerRound`), carrying the market helpers from `functions/coinjoin` and the PoDLE functions from `functions/podle` as statics. Errors from PoDLE now start `coinjoin:`. **Renamed:** `planCoinjoin` → `Coinjoin.plan`, `buildCoinjoinPsbt` → `Coinjoin.buildPsbt`, `describeCoinjoinPsbt` → `Coinjoin.describePsbt`, `validateCoinjoinForMaker` / `validateCoinjoinForTaker` → `Coinjoin.validateForMaker` / `validateForTaker`, `finalizeCoinjoin` → `Coinjoin.finalize`, `commitmentOf` → `Coinjoin.podleCommitment`, `nextIndex` → `Coinjoin.nextPodleIndex`, `generatorJ` → `Coinjoin.podleGenerator`, podle `DEFAULT_MIN_AGE_CONFS` / `DEFAULT_MIN_VALUE_PCT` → `Coinjoin.PODLE_MIN_AGE_CONFS` / `PODLE_MIN_VALUE_PCT`; every other export keeps its name. **Removed:** `functions/coinjoin`, `functions/podle`.
- **`types/bond`** (`Bond`) now also builds and checks coinjoin fidelity bonds, from `functions/fidelityBond`, as statics. Scripts, certificates (`type: 'FidelityBondCertificate'`) and the offer field `fidelityBond` are unchanged; errors start `Bond:`. **Renamed:** `bondPath` → `Bond.fidelityPath`, `isValidLocktime` → `Bond.isValidFidelityLocktime`, `bondLocktimes` → `Bond.fidelityLocktimes`, `buildBondP2tr` → `Bond.buildFidelity`, `buildBondRedeemPsbt` → `Bond.prepareFidelityRedeem`, `signAndExtractBondRedeem` → `Bond.signFidelityRedeem`, `signBondCertificate` → `Bond.signFidelityCertificate`, `normalizeBond` → `Bond.normalizeFidelity`, `verifyBondCertificate` → `Bond.verifyFidelityCertificate`, `bondValue` → `Bond.fidelityValue` (the `bondValue` row field stays), `verifyFidelityBond` → `Bond.verifyFidelity`, `BondVerifier` → `Bond.FidelityVerifier`, and the constants to `Bond.FIDELITY_INTEREST_RATE`, `FIDELITY_EXPONENT`, `FIDELITY_LOCKTIME_GRID`, `FIDELITY_MAX_CERT_BLOCKS`, `FIDELITY_MIN_CONFS`, `FIDELITY_CERTIFICATE_TYPE` (`YEAR_BLOCKS` keeps its name). **Removed:** `functions/fidelityBond`.
- **`types/policy`** (`Policy`, also `Fabric.Policy`): contract spend policies. It merges `functions/contractTaproot` (failover ladder → P2TR, leaves, trees, PSBT preparation and finalization, the federation vault), `functions/contractTierWhen` (off-chain `when` predicates), and `functions/programTaprootBind` (Program-run hashlock leaves). `new Policy(settings)` takes a ladder, `validators` inputs, or another Policy and holds the normalized policy as its own fields, so an instance goes wherever a policy object did; it adds `address`, `compile()`, `leaves()`, `activeTiers(ctx)`, `migrateTarget(ctx)`, `afterDecay(atLock)`, `withRunHashlock(run, opts)`, and `toJSON()`. Statics take and return plain objects as before. Addresses, scripts, and PSBTs are unchanged. **Renamed:** `normalizeContractSpendPolicy` → `Policy.normalize`, `buildContractTaproot` → `Policy.compile`, `policyAfterDecay` → `Policy.afterDecay`, `composePolicyWithRunHashlock` → `Policy.withRunHashlock`, `getPath` → `Policy.tierWhenPath`, `OPS` → `Policy.TIER_WHEN_OPS`; every other export keeps its name (`Policy.toAddress`, `Policy.selectActiveTiers`, `Policy.evaluateTierWhen`, `Policy.hashlockFromProgramRun`, …). Errors that named the old functions now start `Policy.afterDecay` / `Policy.withRunHashlock:`. **Removed:** `functions/contractTaproot`, `functions/contractTierWhen`, `functions/programTaprootBind`.
- **`types/federation`** (`Federation`) now carries the federation helpers as statics, plus named federations. **Validators** (was `functions/federationValidators`): `uniqueValidatorPubkeys`, `findValidatorEntry`, `witnessSignatureFor` keep their names; **renamed** `federationValidatorId` → `Federation.validatorId`, `normalizeFederationValidators` → `Federation.normalizeValidators`, `resolveFederationThreshold` → `Federation.resolveThreshold`, `federationThresholdExceedsValidators` → `Federation.thresholdExceedsValidators`. **Pre-sign gate** (was `functions/federationValidatorVerify`): `verifyLocalEpochDigests`, `verifyReserveConservation`, `verifyProgramRunRecompute`, `evaluateValidatorSignGate`, same names. **Reserve ledger** (was `functions/federationReserveLedger`): every function and constant keeps its name (`Federation.applyPegInCredit`, `Federation.RESERVE_KEY`, …) except `defaultFederationSidechainPolicy` → `Federation.defaultSidechainPolicy`. **Named federations**, moved from Hub (`functions/federationDescriptor`, `functions/federationWithdrawal`) so every member (Hub, Passport, any key) shares one implementation: `buildDescriptor`, `canonicalDescriptor`, `descriptorId`, `vaultForDescriptor`, `isValidator`, `withdrawalRequestId`, `prepareWithdrawal`, `signWithdrawal`, `addWithdrawalSignatures`, `finalizeWithdrawal`, the member message builders (`inviteMessage`, `responseMessage`, `syncMessage`, `withdrawalMessage`, `signatureMessage`, `broadcastMessage`, `isMessage`, `MESSAGE_TYPES`) and checks (`verifyInvite`, `verifySender`, `verifyWithdrawalRequest`). Federation ids, vault addresses, and withdrawal request ids are unchanged. **Removed:** `functions/federationValidators`, `functions/federationValidatorVerify`, `functions/federationReserveLedger`.
- **One document tree, no protocol versions (breaking).** Every document, sealed or not, uses the domain-separated, count-bound tree (leaf `SHA256(0x00‖blobHash‖paymentHash‖iv)`, zero fields when absent); the Bitcoin-style blob-hash tree, `treeVersion`, `DOCUMENT_TREE_VERSION`, `Document.MANIFEST_VERSION`, `plainBlobRoot`, `accumulateBlobLeaf`, and `blobHashesMutated` are removed, and `createBlobMerkleTree` moves to `Challenge.createBlobMerkleTree` (storage challenges keep their own tree). Every sealed frame must carry an inclusion proof, and a whole-document sealed sale commits its `SHA256(K)` on every leaf. Unindexed whole-body frames are flagged `unindexed` (was `legacy`); `DocumentBook` offers lose `leavesCommitted`. Document ids, payment hashes, and offers made before this change do not verify; republish them. Test vectors are regenerated.
- **`Message` statics:** `padDigits`, the header `parent` helpers (`ZERO_PARENT`, `isZeroParent`, `normalizeParent`, `parentHexOf`, `frameIdOf`, `setMessageParent`), `HEADER_OFFSETS`, `verifyFrameAuthor`, and the legacy-body codec (`fromLegacyBody`, `encodeLegacyBody`, `decodeLegacyBody`, `tryParseLegacyBody`, `canonicalPeeringObject`, `LEGACY_BODY_TYPES`) now live on `types/message`. **Removed:** `functions/padDigits`, `fabricMessageParent`, `fabricFrameAuthor` and `fabricMessageBodies`. Renamed on the way: `buildMessage` → `Message.fromLegacyBody`, `decodeToLegacyBody` → `decodeLegacyBody`, `normalizeParentHex` → `normalizeParent`, `OFFSETS` → `HEADER_OFFSETS`.

Convergent seeding market: identical chunks de-duplicate across sellers and documents, and seeders earn per chunk without an HTLC. Fixed-size segmentation only (no content-defined chunking). See [docs/L1_DOCUMENT_EXCHANGE.md](docs/L1_DOCUMENT_EXCHANGE.md).

- **Convergent sealing is the default.** `Document.seal` derives each chunk key from the chunk (`aes-256-gcm-convergent`: `K_i = taggedHash('Fabric/DocumentConvergentKey', …)`, IV from the key), so the same plaintext seals to the same ciphertext, blob hash, and payment hash for everyone. `{ private: true }` keeps random keys (`aes-256-gcm-content`); `{ convergenceSecret }` scopes de-duplication to holders of a secret. `Document#convergent`, `setConvergenceSecret`, and the record field `convergence` (`'public'` | `'scoped'` | `null`) are new; `functions/documentSealedExchange` exports `convergentKey`, `convergentIv`, `CONVERGENT_SCHEME`, `SEALED_SCHEMES`.
- **Breaking:** `Peer#publishSealedDocument` lists a convergent document under its `merkleRootHex`; a custom `documentId` becomes a local label only. Two `seal` calls on the same bytes now produce identical ciphertext, so code or tests that expect different ciphertext (or a custom id on the wire) must seal with `private: true`.
- **De-duplication:** `Peer` keeps opened convergent chunks (`maxHeldChunkBytes`, default `PEER_MAX_HELD_CHUNK_BYTES`) and opens a matching chunk of another document from there (`heldChunk`, `adoptHeldChunk`); `Market` skips buying a held chunk and counts a chunk as covered across document ids.
- **Seed after download:** `Peer#seedableDocument` / `seedDocument(id, terms)` sell a received convergent tree again as the same tree from the held chunks (nothing is resealed); `documentReceived` carries `seedable`; `Market({ seed })` seeds every such download (`seeded`).
- **Channel balance transfers:** `Channel.Session#transfer({ amountSats, ref })` moves balance with no HTLC (`ChannelCommitment` `transfer` field; reserve, HTLC, and fee checks on receive; a paid ref is refused). `ChannelBook#transfer`, and a seller credit ledger: `extendCredit`, `outstanding`, `listCredits`, `creditLimitSats`; events `transferReceived`, `creditExtended`, `creditSettled`; credits are exported with the book.
- **Pay after verify (credit rail):** `publishSealedDocument(doc, { creditRateSats, creditLimitSats })` (convergent documents only) adds `creditRateSats` and `paymentModes: ['htlc', 'credit']` to inventory. A `DocumentRequest` with `credit: true, creditRef` gets the key before payment when the seller's `settings.sealedBlobCredit(request)` agrees (event `documentBlobCredit`); `requestDocument(…, { credit, creditRef })` sends one. `Market` (`credit`, default on) takes that rail when an open channel to the seller can pay it, and pays with a channel transfer only after the blob opens from that seller's key (`creditTransferred`); a wrong key is never paid. No HTLC means no 716-sat floor per chunk.
- **Hub:** the document-market republish seeds a received convergent tree through the agent `Peer` instead of resealing it (guarded, so an older core pin keeps the old path).

BIP helpers: one copy of each, checked against the official test vectors.

- **Breaking:** `functions/bip69` no longer exports `p2shP2wpkhPayment` / `p2shP2wpkhAddress`; import them from `functions/bip49`. The compressed-key parser is `asCompressedPubkey` in `functions/bip67` (shared by BIP-49 and BIP-67; error messages drop the `BIP49` / `BIP67` prefix). `types/channel` and `types/policy` use `BIP125_SEQUENCE_LOCKTIME_ONLY` from `functions/bip125` instead of their own `SEQUENCE_NONFINAL`.
- **`functions/bip21`** follows BIP-21 / BIP-321: query components are RFC 3986 percent-encoded (a space is `%20`, `+` is a literal plus; it was form-encoded), keys are case-insensitive (`AMOUNT=`, uppercase QR URIs), `amount` / `label` / `message` / `pop` / `pj` / `pjos` may appear once, other repeated keys parse to an array (and an array in `extras` encodes as a repeated key), the address may be empty only when a query key carries the payment instruction, and amounts finer than one satoshi are refused.
- **`functions/bip69`** compares output amounts as uint64 (`BigInt`), so amounts above 2^53 sort correctly.
- **`functions/bip32`** refuses to derive a child past depth 255 (the serialization limit).
- **Tests:** BIP-32 test vectors 1–5 (including CKDpub from each parent xpub and every invalid key in vector 5), the 24 English BIP-39 vectors (`TREZOR` passphrase, through to the master xprv), the four BIP-67 vectors (redeem script and address), the full BIP-49 vector, and the BIP-321 examples and invalid URIs. The BIP-67, BIP-69, and BIP-85 suites have their own files; BIP-85 already matched every spec vector.

One copy of each shared helper in `functions/`. **Breaking:** the re-exports below are removed, not kept as shims. Digests, addresses, and wire bodies are unchanged.

- **`functions/pubkey`** (new) holds `pubkeyXOnly`, `pubkeyCompressed`, and `pubkeysMatch`. **Removed:** `pubkeyXOnly` / `pubkeyCompressed` from `functions/groupChatSeal`, `pubkeyXOnly` from `functions/fabricChatText` (which also stops re-exporting `functions/fabricChatKind`), and `pubkeyXOnly` / `pubkeysMatch` from `functions/identityCrossSignVerify`.
- **`functions/bytes`** `toBuffer(input, label)` (Buffer, Uint8Array, or hex with optional `0x`) replaces the private `asBuf` in `musig2` / `musig2Session` and `asBuffer` in `bip69` / `bip371`. **Removed:** the `asBuffer` export of `functions/bip371`.
- **`functions/sidechainState`** is the home of `normalizeContractId` and `stateDigest` (`stateDigest(null)` now hashes the empty state). **Removed:** `normalizeContractId` / `stateDigest` from `functions/contractMessageAccumulate`, `normalizeContractId` / `bufferFromPaste` from `functions/contractMessageQueue`, the `contractProgramBind` re-exports of `functions/contractSpend` (`programMetaFromTip`, `requiresProgramBind`, `bindProgramRunToTip`, `validateProgramRunBinding`), the `SIDECHAIN_*_PATH` exports of `functions/beaconNetworkGuard`, and the Statechain re-exports, `storePathsForContract` alias, and `fromCore` flag of `functions/contractSidechainLocal`. `contractMessageAccumulate` and `contractSpend` hash through `functions/fabricCanonicalJson` instead of their own canonical stringify. Strings over 90 characters are refused, and every decode failure throws `Invalid bech32 string`. `Key` builds P2TR addresses with `encodeSegwitAddress` instead of its own bech32m encoder; `BECH32M_CHARSET` is gone from `constants` (use `bech32.CHARSET`).

**Breaking: `Key#deriveAddress(…, 'p2tr')` now returns standard BIP-86 addresses.** The output key is the BIP-341 key-path tweak with no script tree, `taggedHash('TapTweak', P_x)`. Before, `Key` tweaked with plain SHA-256 of the x-only key followed by 32 zero bytes, so every P2TR address it derived was nonstandard: other wallets did not derive it, and no Fabric signer could spend from it. Its addresses now match the BIP-86 test vectors (pinned in `tests/fabric.key.js`) and the key-path signer in `types/coinjoin`. ## 2026-07-29
JS-canonical protocol for 0.1.0; Lightning-style wire preimage; unsigned document binding; public-readiness cuts; Peer scoring; directed onion forward.

**P2P_FORWARD (onion / IP privacy)**
- New opcode **`P2P_FORWARD` (0x45)** with V1 field body `{ nextPeer, ttl, inner }`.
- Helpers: `@fabric/core/functions/fabricOnion` (`wrapOnionPath`, `wrapForwardLayer`, `tryDecodeForward`).
- `Peer#sendOnion(path, payload)` writes only to the first hop; peers peel when `nextPeer` matches local x-only pubkey, else forward bit-identical to that peer (no mesh flood).
- `P2P_RELAY` remains the flood envelope — use `P2P_FORWARD` when protecting peer IPs.

**Install / C**
- **npm install skips `fabric.node`** by default (`scripts/install-native.js`). Opt in with `FABRIC_BUILD_NATIVE=1` or `npm run build:c`. C sources remain in-tree; JS Message/Peer is the protocol oracle ([`docs/C-JS-PARITY.md`](docs/C-JS-PARITY.md)).
